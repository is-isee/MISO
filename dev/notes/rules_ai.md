# AI (コーディングエージェント) 利用のルール

MISO の開発で Claude Code/Codex などの AI コーディングエージェントを使う際のルール。
Pull Request (PR) は堀田、飯島どちらかの承認が必要。PRを作成した人が承認することはできない。
この前提で、AI を使ってもレビュー負荷が増えないことを最優先にする。

## 1. 役割と責任

- AI の役割は「下書き・調査・テスト実行・レビュー補助」に限る。
- コードの責任は PR 作者 (人間) が負う。作者は AI が書いた差分を自分で読み、内容を説明できる状態で PR を出す。
- AI に判断を任せない項目: 物理・数値スキームの変更、公開 API の変更、依存ライブラリの追加、リポジトリ構成の変更。これらは issue で人間同士が合意してから着手する。

## 2. ブランチと PR

- AI は作者のブランチ (`<github-id>/issueNNN`) 上でのみ作業する。`main` には触らない。
- `git push`、PR 作成、issue へのコメント投稿は人間が指示したときだけ行う。GitHub 上に現れる発言はすべて人間のアカウントの責任とする。
- 1 PR 1 テーマ。目安は差分 200 行以下。AI が関与した open PR は同時に 1 本まで (最大 2 本)。前の PR がマージされてから次を出す。
- 差分が大きくなる変更 (機械的な置換など) は、issue で方針を合意してから、レビューしやすい単位に分割する。

## 3. PR 本文に必ず書くこと

PRの下書きをAIに書かせても良い。

1. 変更理由 (対応する issue 番号)
2. 検証方法と結果 (実行したコマンド、テストの pass 数、比較した数値)
3. 数値結果への影響の有無 (「ビット単位で同一」「丸め誤差程度」「物理的に変わる」のいずれか)
4. AI 利用の明示 (Claude Code/Codex が付ける自動フッターでよい)
5. レビュアーに特に見てほしい箇所

## 4. 検証の最低基準

- CPU ビルドと `ctest` が通ること。
- 数値に触る変更は、変更前後でデモを実行して出力を比較し、その数値を PR に貼る。
- GPU に触る変更は、GPU で実行してから PR を出す。
- フォーマッタ (clang-format, ruff) を通してから PR を出す。

## 5. AI をレビューに使う場合

- 相手の PR を AI に事前レビューさせてよい。ただし GitHub へのコメントは人間が内容を理解して、責任を持つこと。
- AI の指摘をそのまま貼らない。採用しない指摘は書かない。

## 6. 情報の扱い

- MISO は公開リポジトリなので、リポジトリ内の情報は AI に渡してよい。
- 未公開の研究データ、他プロジェクトの非公開コード、認証情報は AI に渡さない。

## 7. 共有知識の置き場所

- AI に毎回伝える必要のあるプロジェクト情報 (ビルド手順、規約、禁止事項) はリポジトリ直下の `CLAUDE.md` に書く。
- 個人の AI ツールが持つメモリ (端末ごとの記憶) は共有されないので、共有すべき内容はリポジトリに書く。

## 8. ルールの改訂

- このファイルの変更も通常の PR として出し、相手の承認を得る。
- 運用してみて負担が大きい・足りない点があれば issue で提案する。
